## Stage 2 — Cut prompt size — DONE

- `daemon/src/services/context.ts`: `buildContextPack` now takes `scope: 'repo' | 'task'`. Repo scope (plan, prompt drafting, implement) keeps the file list + README. Task scope (qa, review, fix, analyse) drops the repo tour entirely — only the task's changed files, with excerpts only for tool-less adapters when they beat the diff. `errors` now attach only in repo scope; every pack carries `budgetChars`.
- `daemon/src/engine/engine.ts`: `packFor(repo, task, c, wanted, kind?, { diffChars? })` picks the scope by work-item kind; `deskPack(c, wanted, hash)` gives prompt-pipeline/accept items a real budget with zero repo context. `dispatchQa`/`dispatchReview` compute the diff first so `packFor` can skip file excerpts when the capped diff is smaller.
- `daemon/src/engine/prompts.ts`: `renderPrompt` returns `{ text, dropped, budgetChars }` — stable prefix (header, role, goal, task brief, contract) first, volatile data blocks in fixed order after; over-budget → drop in order skills (exec-time) → repo summary → file excerpts → team inbox → errors, then mid-truncate remaining blocks. `finalizeApprovedPrompt` does the same budget fit for pipeline-approved prompts. Inbox capped to the newest 4 messages / 3k chars; diffs capped via `capDiff`, logs via `compactLog`.
- `daemon/src/util.ts`: `compactLog` (collapses repeated lines, keeps first failure block + tail) and `capDiff` (truncates at `diff --git` boundaries, reports omitted-file count).
- `daemon/src/db.ts`: additive `prompt_versions.dropped` + `prompt_versions.budget_chars` columns via the existing idempotent `addColumn` convention — no migration script, existing DBs upgrade in place on open. `createWorkItemRecord` stores them; `executeWorkItem` drops the skills block first and records it; `prompt.trimmed` events emitted.
- Tests: `daemon/tests/prompt-size.test.js` (8 tests — scope behavior, stable ordering, drop recording, inbox budget, capDiff, compactLog). 63/63 pass, typecheck clean.
- Demo (scripted run `01M58Y9QGSGRE1WFGWFWAQY9D6`, scratch data dir, 1 task): total 30,251 prompt chars across 10 items. ## Stage 3 — Structured agent-to-agent hand-offs — DONE

- `daemon/src/services/handoffs.ts` (new): `handoffEnvelope(task, toRole)` builds the typed envelope `{fromRole,toRole,taskId,status,summary≤400,filesChanged,checksRun,openQuestions,decisions,blockers}` from stored facts (last delivered work item, check_runs, task messages, open error reports), persists it in the existing `handoffs` table and emits `task.handoff`. `validateReply(kind, j)` is the hand-written strict-shape validator for pm/prompt-creator/reviewer/qa replies.
- `engine.ts`: envelopes injected as a `HANDOFF` data block at every stage transition (implement, qa, review, fix, accept); a fixer's envelope carries the findings as `blockers` (full findings stay — the recipient needs them); reviewer gets the QA report only when QA could not run / acceptance needs it. `handleDelivered` validates strict kinds before routing; on invalid output `repairReply` dispatches one repair work item whose prompt is only the validation error + the bad output (≤6k), then falls back to the previous lenient parsing. Repair items are ordinary work items → counted in the token report. Prompt-pipeline jobs are re-keyed to the repair item so a repaired draft still flows to PM review.
- `messages.ts`: `takeInbox` rewritten — broadcasts deliver to each agent at most once via `message_deliveries` (per-agent tracking replaces "latest 8 in every prompt"); messages on finished tasks are never delivered; direct/role mail still marks `read_at`. `postMessage` drops a new message ≥90% similar (normalized token-set Jaccard) to an unread one from the same sender to the same recipient, emitting `agent.msg.dropped`.
- `db.ts`: `CREATE TABLE IF NOT EXISTS message_deliveries (message_id, agent_id, delivered_at)` — additive, same convention.
- Tests: `daemon/tests/handoffs.test.js` (5 tests — envelope contents/persistence/cap, once-per-agent broadcast delivery, finished-task exclusion, dedupe, validator shapes). 68/68 pass, typecheck clean.
- README "Flow" section updated (typed hand-offs, strict JSON + repair retry, delivered-not-repeated messages).

## Stage 4 — Reliability and recovery — DONE

- `daemon/src/services/failure.ts` (new): `classifyFailure(msg)` → `transient` (rate limit, network, timeout, 5xx, CLI crash — and unknown errors, safest there), `model-quality` (invalid/empty/unparseable output), `fatal` (auth/permission, missing CLI/ENOENT, repo/worktree conflict). `backoffDelayMs(attempt)` = exponential 2s→60s cap + 0–50% jitter. `fixHintFor(msg)` = the one-sentence concrete fix. `notifyOnce(run, action, task, …)` raises a single pending Needs-you per (run, action, task).
- `engine.ts` `handleWorkItemFailure`: fatal → task `waiting-input`, run paused, exactly one `run.fatal` approval carrying `fixHintFor`. Transient → task attempts counted, exponential backoff with jitter before requeue to `ready` (plan items retry immediately ≤3 as before; provider failover still happens inside `dispatchThroughAdapter`'s option loop). Model-quality dispatch failures → one escalation to a stronger tier (`difficulty +2`, guarded by `meta.tierEscalated`) before the attempt budget burns.
- PM diagnosis before human escalation: when a task exhausts `sameErrorAttempts` dispatches, `dispatchDiagnosis` gives the PM a `diagnose` work item (desk pack, failure history + approved prompt). Strict JSON reply `{diagnosis, strategy, splits[]}` — `retry-stronger` resets attempts at higher difficulty, `split` creates ≤3 subtasks and cancels the parent, anything else → `task.escalate` approval with the diagnosis attached. Guarded once-per-task by `meta.diagnosed`. New work-item kind `diagnose` wired through `WorkItemKind`, ROLE_WORK, roleNameFor, AGENT_STATE, EST_COST, scripted adapter and the Skills page kind list.
- Ceilings pause, never kill: run budget and wallclock already enforced — both now return `CEILING:` reasons that `notifyOnce` + `run.ceiling` event + pause. New optional `limits.maxTaskMinutes` per-task time ceiling (any work item running longer). Task cost ceiling: when `spent_usd > budget_usd` the task goes `waiting-input`, one `task.budget` Needs-you, run paused.
- Crash recovery: `reconcileOnBoot` (existing) marks stale `running` work items `interrupted` and their tasks `ready` again — covered by a new test that simulates a crash. Idempotent requeue: `createWorkItemRecord`'s idempotency key is now `task:kind:len:sha256(prompt)` (was `Date.now()` — could never dedupe); a live item with the same key is reused instead of duplicated.
- Windows process-tree kill: `cli-resolve.ts` `killProcessTree(child)` uses `taskkill /PID /T /F` (POSIX: SIGKILL on the child). `cli.ts` registers every spawned child in `liveChildren`; hard timeout kills the tree; `killCliChildrenForRun(runId)` is invoked from `stopRun` and hard `pauseRun`, so a run stop ends hung CLI subtrees. A cancelled/killed work item can no longer deliver (guard in `executeWorkItem`).
- Tests: `daemon/tests/reliability.test.js` (6 tests — classification, backoff bounds+jitter, fix hints, notifyOnce dedupe, crash→interrupted→requeue idempotently, stable-key dedupe of live work items). 74/74 pass, typecheck clean. Scripted demo run `01M58Z7M1HT2NZF2DJD6C5W0WP` completed `done` end-to-end on a scratch data dir.

## Stage 6 — Missing workflow features — DONE

- **Read-only lane (6.1):** `limits.maxReadOnly` (default 2, overridable per run via `POST /api/runs` `limits`). In direct mode, while a writer holds the repo, non-overlapping ready tasks run their prompt draft→PM-review pipeline on a desk (`treeWait`/`promptReady` meta flags, `task.lane` event); the parked prompt resumes when the tree frees. Writers still never overlap — `lockedPaths` guards both lanes.
- **Result cache (6.2):** `work_items.cache_key` = sha256(kind + prompt text + context-pack hash + model id). An identical dispatch hits the cache in `executeWorkItem` — the prior delivered result is reused, zero adapter call, `cache.hit` + activity events, and `tokenReport` returns `cache: {hits, savedPromptChars, savedTokens}` (saved = what the source item spent). "Cache hit" shows in Live activity and the token report.
- **Derived checks (6.3):** `deriveChecks(repoId, criteria)` in `verify.ts` maps each acceptance criterion to a runnable repo check — by name mention, command mention, or keyword→kind hint (tests/build/lint/security/docs); doc checks count as runnable via pass-rule. `applyPlanDiff` stores `meta.derivedChecks`/`meta.nonCheckable` per task, flags uncovered DoD items (`checkable:false`, `dod.flagged` event), and the implement prompt shows "Verified by checks:" + "Criteria without a runnable check". Dod page shows "not machine-checkable — judged at review".
- **Scope guard (6.4):** `verifyDeliveredTask` compares delivered files to `task.affectedPaths`; unexpected files emit `scope.violation`, post a `question` message to the PM (seen at accept time), and stamp `meta.scopeViolation`. Non-blocking — the PM decides whether the extra files belong.
- **Per-repo lessons (6.5):** `error_kb` extended (not duplicated) with `repo_id` + `times_seen` upserts. `recordReviewerFlag` turns repeated reviewer rejections into "Avoid:" lessons; `resolveError` fills `repo_id`. `lessonsFor` injects ≤3 keyword/path-ranked lessons ≤1200 chars (~300 tokens) into implement + fix prompts (`KB_MATCHES` block, `lessons.injected` event). - **Run summary (6.6):** `services/summary.ts` builds it from tables only — goal, tasks+status+owner, commits (`commit.created` events), check totals, tokens/cost per stage + cache savings, retries (re-attempts + repairs), human interventions (decided approvals minus auto-approvals, owner messages). `finalizeRunSummary` stores `runs.summary_md` at terminal status; `GET /api/runs/:id/summary` re-derives live or serves stored; `?format=md` downloads Markdown. ## Stage 7 — Performance and final audit — DONE

- **Benchmark first.** `daemon/scripts/bench.mjs` runs a fixed scripted scenario (direct mode, prompt-review-all, auto commits, PM sends back the first brief, first delivery fails checks, first reviews fail, DoD includes `git:diff`). First run exposed a real Stage-6 regression: a parked read-only-lane task resumed with `worktree` still `NULL` — `verifyDeliveredTask`'s `task.worktree!` crashed (`path must be of type string`), classified transient, retried forever; run timed out at 240s with one task stuck `ready` and DoD D1 failing. Fixed in `dispatchApprovedPrompt` (assigns `worktree`/`branch` when dispatching a parked direct-mode job). Also added a FATAL class for engine-side crashes (`must be of type`/`Received null`/…) — deterministic bugs must pause, not backoff-loop.
- **Before/after:** before = `timeout(running)` at 240s, 21 work items, 267 events, 1 failed/interrupted, DoD `D1:fail`. After = `done` in **27s**, 23 work items, 310 events, 20 check runs, 0 failed/interrupted, DoD `F1:pass Q1:pass Q2:pass R1:pass D1:pass C1:pass`.
- **Indexes** (`db.ts`, additive `CREATE INDEX IF NOT EXISTS`): `idx_wi_task work_items(task_id,status)`, `idx_msg_run_read agent_messages(run_id,read_at)`, `idx_events_run_ts events(run_id,ts)` (existing `idx_events_run (run_id,seq)` already covers ordered listing), `idx_wi_cache work_items(cache_key,status)`, `idx_err_sig error_reports(signature,status)`, `idx_repo_checkpoints`.
- **N+1:** `messages.ts` `formatInbox`/name resolution preloads agent names into a map instead of one `SELECT` per message.
- **WS payloads:** broadcasts now cap string fields at 2000 chars with a `<field>Truncated` marker (`slim()` in `server.ts`); full event stays in the DB and is served on demand via `GET /api/events/:seq`. Worst-case broadcast ≈6× smaller (12k-char `detail` fields were the norm for prompt events).
- **Sync git on hot paths:** `snapshot.ts` adds `snapshotTreeRecent` (memoized recent tree) and async helpers; engine hot paths (`taskFiles`, `taskDiff`, `runChangedFiles`, DoD evaluation incl. a bounded `dodCache` keyed on repo+check+tree) moved off repeated synchronous `git` calls.
- **UI:** Activity feed caps in-memory events, throttles ingestion, and lazy-loads truncated fields; Timeline caps the rendered list with explicit load-more. WS-driven invalidation already excluded stream events.
- **Tests:** 85/85 pass; `npm run typecheck -w daemon` clean; `npm run build -w ui` clean. README "State of the implementation" rewritten + remaining risks listed.
- Chose not to do: an A/B bench of perf changes alone (the pre-fix tree cannot finish the scenario — the hang dominates; the 27s completion vs 240s timeout is the honest before/after). No new tests for the parked-worktree fix — it is exercised end-to-end by the bench scenario (docs task parks then resumes).
