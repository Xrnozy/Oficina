## Phase 2 — Engine executes the graph — DONE

- **Types:** `WorkItemKind` gains `'custom'` (any node purpose not mappable to a pipeline kind); `EST_COST` gets a `custom` entry (`routing.ts`); `rows.ts` maps `workflow_node_id`/`workflow_edge_id` on `WorkItem`.
- **`workflow.ts`:** cycle validation relaxed to cycle-membership semantics — a directed cycle is legal iff at least one edge in it is `on-failure`/`on-reject` (which carries the loop bound); error names the offending cycle. Default graph edge kinds adjusted to fit the rule.
- **`engine.ts` — graph executor (~450 lines before `wireEngineEvents`):**
  - `graphFor(run)` resolves + memoizes the run's pinned workflow version; `createRun` stamps `workflow_version_id` from `activeWorkflowFor` (null → untouched legacy path).
  - `wfState`/`saveWfState` keep per-task traversal in `task.meta.wf`: in-flight `nodes`, completed `fired`, `loops` per bounded edge, `arrived` per merge node, `awaiting` gate, `queued` writers, `draft` for prompt loops, `lastOutcome`.
  - `graphTaskEntry` walks start→entry nodes (run-scope `plan` nodes execute once per run via `dispatchPlan`); `wfEntryNodes` exported for tests.
  - `dispatchAgentNode` builds the node's work item (`purpose`→kind, role/pinned-agent/agentId candidate, `modelTier`→difficulty, `instructions`→new `nodeInstructions` prompt block, `inputs` envelope|full|named-node outputs, `writable` default by kind, `budgetChars`), stamps `workflow_node_id`/`workflow_edge_id` on row + in-memory object, parks a second writer (`queued`), and dispatches through `executeWorkItem`.
  - `graphHandleDelivered` (hooked in `handleDelivered`) turns the result into a `WfOutcome` (status/verdict/checks/files/report), fires `message` edges (postMessage + optional `waitForReply` pause with a timer), and `graphAdvanceFrom` picks matching edges (condition eval via `wfFieldValue`/`wfEval`), falls back to `else`, applies `maxLoops` (default 3 on loop-kind edges) and emits `workflow.step`/`branch`/`loop`/`merge`/`deadend`/`human`.
  - Gates: `human` nodes → `workflow.human` approval; loop exhaustion → `workflow.loop`; dead end / starved merge / no eligible agent → `workflow.deadend`. The approval wiring resumes via `graphResume` (reject on a loop edge fails the task; approve grants one more pass; dead-end approve retries the node).
  - Parallel: multiple matching edges dispatch sibling nodes concurrently; merge nodes wait `all`/`any`; writer nodes serialize per task through the repo tree; `end` marks the task approved and proceeds to merge.
- **Two real bugs the loop tests exposed (Stage 6 cache interactions):**
  - Cross-task reuse: `cache.hit` replayed a *different* run's QA verdict because scripted plans produce identically-titled tasks → identical prompts. Cache lookup now requires `task_id IS wi.taskId` — a cached result can only serve the task it verified.
  - Retry poisoning: re-entering an already-`fired` node is a retry — the identical prompt would `cache.hit` and replay the failing verdict forever. Node re-entry NULLs `cache_key` on row **and** the in-memory `wi` (the lookup reads `wi.cacheKey`, not the row).
- **Tests `daemon/tests/workflow-graph-exec.test.js`** (6): compat (no active workflow → unchanged legacy `[plan, prompt, prompt-review, implement, qa, accept]`); linear custom graph stamps node+edge ids and reaches `done`; `on-failure` loop re-runs the writer until QA passes; exhausted `on-reject` edge (maxLoops=1) requests `workflow.loop`, owner decision resumes; deterministic condition eval; `wfEntryNodes` walk.
- Results: 6/6 new tests pass; typecheck clean; full suite 94 → **100**.

## Phase 3b — Skills on nodes — DONE

- **Storage choice:** node skill refs live in `node.config.skills = [{skillId, name, versionId?}]` — inside the version's immutable graph JSON, so a run resolves the skills the version had when it was saved **by construction** (spec's "as they were when activated"), with no schema change, no cross-version leakage, and clone/export/import carried for free in the graph. `versionId` pins the approved version at attach time; when absent the ref follows the latest approved version.
- **`skillsFor` (`skills.ts`):** new optional `nodeSkills` + `inheritSkills` params (callers without a node are unchanged). Resolution order node → agent → role, de-duplicated by skill id, node listed order = budget priority. `AppliedSkill.via` gains `'node'`; `SkippedSkill` gains `via`; `skill.applied` payloads now carry the source. Excluded agent/role attachments are reported skipped (`"node skills only"`) so the UI can show them greyed. Return also includes `used`/`budget` (chars) for the meter.
- **`executeWorkItem` (`engine.ts`):** resolves the work item's `workflow_node_id` against the run's pinned graph and passes `config.skills` + the `inheritSkills !== false && !skillsOnly` gate — legacy items pass no node context.
- **Validator:** `config.skills` refs produce node-keyed *warnings* (not errors): unknown skill ("not in this office — import or create it"), disabled, and imported-but-unapproved ("waiting for approval"). At dispatch they're simply skipped with the reason.
- **REST:** `POST /api/skills/node-preview` — skillsFor against a draft node (body: skills/agentId/roleId/kind/inheritSkills) so the inspector's budget meter and greyed list work on unsaved drafts.
- **UI:** agent-node inspector gains a Skills section — attached list with `node` badges, per-skill ~tokens, remove, up/down budget priority; live debounced preview → `applied`/`skipped` with `via` shown greyed ("From the agent / role"), a used/budget meter, an "Add" picker (search, description, ~tokens, `disabled`/`needs approval` chips), inline New-skill and Import-folder actions (import toasts the approval requirement); switches `inheritSkills` + `skillsOnly`; "Apply to all <role> nodes" copies the skill config role-wide. Palette gains a draggable Skills section — drop onto an agent node appends the ref (accent drop ring on hover); attached count shows as a card chip.
- **Tests `daemon/tests/workflow-node-skills.test.js`** (7): no-node unchanged (`via=role`); node-first budget ordering + via=node + dedupe (14k+4k > 16k proves the node won); node-listed order decides budget priority; skillsOnly excludes agent/role with the reason; unapproved import → skipped `no approved version` + validate warning `waiting for approval`; unknown/disabled refs warn without errors; refs round-trip through save/clone.

## Phase 4 — Templates, dry-run, guardrails, warnings, audit — DONE

- **Templates (`workflowTemplates()` in `workflow.ts`):** six graphs that all validate clean — `default` (full pipeline mirror), `fast` (plan→dev→accept, no QA/review loop), `strict` (analyst diagnose + reviewer + human gate before merge), `docs` (task.type condition routes docs tasks to the docs agent), `bugfix` (triage→fix→verify loop bounded at 2), `parallel` (dev fans out to two reviewers, `merge` node waits for both). Served at `GET /api/workflows/templates`; the New button opens a picker (template or blank).
- **Dry run (`simulateWorkflow` in `engine.ts`, `POST /api/workflows/simulate`):** pure walker over a draft graph — no DB writes, no model calls, no tokens. Per-node mocked outcomes (`outcomes: {nodeId: status | [status...]}` — a list scripts successive visits); mirrors real semantics: `wfMatchingEdges` (kind + condition + else), `maxLoops` bounds, parallel fan-out, merge `all`/`any` arrival tracking (each arrival is a step, so the wait is visible), human gates counted and auto-passed, message edges noted. Returns ordered steps (clickable → selects the node), taken edge ids (canvas highlight), `loopsUsed`, `calls`/`humanGates`, `result: end|dead-end|max-steps`, and `notes` (loop-bound hits, dead ends, message sends).
- **Estimate (`estimateWorkflowCalls` in `workflow.ts`):** worst-case agent calls = reachable task/run-scope agents + per loop-edge `maxLoops(default 3) × cycle body`. Cycle body = `fwd(e.to) ∩ rev(e.from)` — correctly counts both endpoints (each pass re-enters `e.to` *and* re-arrives at `e.from`); first draft's stop-at-`e.from` BFS undercounted by the tail node. `humanGates` + `skillChars` (approved-version sizes of node-attached skills) ride along. Returned by `/validate` and `GET /workflows/:id`; shown in the inspector as "worst case per task".
- **Guardrails (`graph.guardrails`, engine-enforced):** `maxStepsPerTask`, `maxStepsPerRun` (run totals live in `run.meta.wfSteps`), `costCeilingUsd`, `timeCeilingMin`. Checked in `dispatchAgentNode` before each dispatch — a tripped ceiling emits `workflow.guardrail`, raises a `workflow.guardrail` approval (Needs-you), sets the task `waiting-input`. Approve → `graphResume` re-enters the node once and adds it to `guardOk` (each ceiling asks once per task); reject → task blocked, owner stops it. The step counter increments only when a dispatch actually happens — queued/parked writers don't burn budget.
- **Referenced-by warnings:** `workflowRefsFor({agentId|roleName})` scans every workspace's effective graph (active custom or builtin) for nodes pinning the agent or naming the role. `POST /agents/:id/fire`, `PUT /agents/:id`, `POST /agents/:id/move`, `DELETE /memberships/:id` compute matches **before** mutating (post-mutation lookups would see nothing) and return `workflowWarnings`; the UI's unassign confirm lists the affected `workflow: node` pairs and toasts the survivors.
- **Audit:** `saveWorkflowVersion` emits `workflow.saved` (existing event) now keyed `entity_id=workflowId` with a `changes` summary (`+2 nodes (x, y), -1 edge`); `workflowAudit(id)` reads that workflow's slice of the hash-chained log; the Versions modal shows the chain-continuity feed.
- **UI:** Templates picker on New; Guardrails fields (4 ceilings, blank=off) + worst-case estimate in the no-selection inspector; Dry-run button (all graphs incl. read-only) → outcome pickers per agent node → step list + taken-edge canvas highlight; version modal audit feed; Agents page unassign warning. Simulation decorations are separate from live-run ones — both can show.
- **Tests `daemon/tests/workflow-safety.test.js` (10):** all templates validate; estimate counts loop bodies (2 agents + 2 passes × 2 = 6); sim happy-path/loop-script/loop-bound-dead-end/condition-vs-taskType-else/parallel-merge/step-cap; refs find pinned agents + role nodes in the effective graph; audit chain continuity + change summary; end-to-end `maxStepsPerTask=1` → one step dispatches, second pauses on `workflow.guardrail`, task `waiting-input`, approve → run completes `done`.
- Results: 10/10 new pass; `npm run typecheck -w daemon` clean; `npm test -w daemon` **117/117**; `npm run build -w ui` clean.
